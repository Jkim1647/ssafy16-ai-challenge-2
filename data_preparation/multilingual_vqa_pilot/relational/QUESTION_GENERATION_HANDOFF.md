# 다단계 VQA 문항 생성 인수인계

## 목적과 입력

대회 형식은 이미지 1장과 한국어 질문, 선지 `a`~`d` 중 정답 하나를 맞히는 VQA다. 여기서는 **두 개 이상의 이미지 근거를 찾아 비교·조합·계산**해야 하는 새 문항을 만든다. 단순 OCR 한 줄 복사, 이미지 없이 선지만 보고 풀리는 문제, 억지 산술은 피한다.

- 후보 목록: `data_preparation/multilingual_vqa_pilot/generated/pilot_300.csv` (일본어 MTVQA 100, 영어 TextVQA 100, 중국어 EST-VQA 100)
- 이미지: `data_preparation/multilingual_vqa_pilot/generated/images/<source>/<number>.jpg`
- 기존 50문항의 **편집 원본**: `data_preparation/multilingual_vqa_pilot/relational/build_multistep_50.py`
- 편집 원본이 생성하는 평가 입력: `data_preparation/multilingual_vqa_pilot/relational/multistep_50.json`
- 사람 검토용 결과: `outputs/multilingual_vqa_relational_20260922/multistep_50_human_review.csv`
- 문항 ID로 이름 붙인 이미지 ZIP: `outputs/multilingual_vqa_relational_20260922/multistep_50_images.zip`
- 재검수 후 로컬 35B 비교: `runs/20260922-multistep50-35b-r3-reviewed/paired_evaluation.json` (35/50 임시 라벨 일치, 227.72초; 공식 정확도 아님)

`pilot_300.csv`의 기존 질문·정답은 후보를 찾는 보조 정보일 뿐 새 문항의 정답 근거가 아니다. 반드시 **원본 이미지**를 확대 확인한다. 이미지 속 글자가 판독 불가하면 숫자·문자 그대로 맞히는 문제를 만들지 않는다. 중국어 EST-VQA 이미지의 재배포·학습 이용 권리는 아직 확인되지 않았으므로 검토 범위 밖 사용을 보류한다. 대회 규정상 외부 모델 API로 추론하지 않는다.

## 생성 단위와 품질 기준

1. 가능하면 **서로 다른 이미지 한 장당 한 문항**을 우선한다. 기존 50문항은 이미지 18장에서 파생되어 평가 문항끼리 상관이 높다. 다음 묶음은 고유 이미지 수를 늘리고 언어별 수를 기록한다.
2. 한 이미지에서 시각 근거 2개 이상을 먼저 메모한다. 예: 왼쪽 메뉴 가격과 오른쪽 메뉴 가격, 낮·밤 주차 단위요금, 위·아래 간판의 전화번호, 서로 다른 동전의 연도. 그 뒤 그 근거를 연결하는 질문을 쓴다.
3. 질문만으로 답이 드러나지 않게 하고, 위치·대상·단위를 명시한다. 다국어 텍스트는 한국어 질문으로 묻되 원문의 뜻을 과장하지 않는다. 외부 상식이나 추측이 필요한 정답은 제외한다.
4. 수치는 원본 이미지에서 두 번 확인한다. `이상`, `약`, `최대`, 세전/세후, 영업시간 경계, 기간의 시작·끝을 그대로 보존한다. **하한값 둘의 차이나 비율을 실제 값처럼 묻지 않는다.** 비교 기간이 서로 겹치는지도 확인한다.
5. a~d는 같은 종류·단위로 만들고 유일한 정답 하나만 남긴다. 정답 위치는 묶음 전체에서 균형 있게 섞는다. 오답은 사진에서 나오는 경쟁 정보나 타당한 계산 실수에 기반하되, 다른 선지도 사실상 정답이 되는지 역검증한다.
6. 각 문항의 `evidence`에는 이미지의 **두 근거와 위치, 필요한 계산 또는 관계**를 적는다. 검수 전에는 `review_status=pending_human`, `training_eligible="false"`를 유지한다. 모델 답변이 초안과 일치해도 사람 검수를 대신하지 않는다.

## 생성 절차

1. `pilot_300.csv`에서 후보 이미지 경로와 ID를 확인하고, 사진을 원본 해상도로 본다. 흐릿한 글자는 제외하거나 명확한 객체·색·위치 관계로 질문을 바꾼다.
2. 질문·선지·초안 정답·시각 근거를 작성한다. 기존 50문항을 수정할 때는 JSON/CSV를 직접 고치지 말고 `build_multistep_50.py`의 `SPECS`를 고친 뒤 다시 실행한다. 이 스크립트가 문항 ID를 유지하며 정답 위치를 균형 배치한다.
3. 생성된 JSON의 50개 ID·이미지 경로·선지 고유성·정답 분포를 검증한다. 각 사진과 문항을 다시 대조해 오역, 중복 정답, 누락된 조건, 같은 이미지의 거의 동일한 문제를 잡는다.
4. 로컬 35B 시험은 `scripts/run_gguf_relational_pilot.py`로 한다. 동일 이미지의 기존 단일 단계 질문과 짝지어 **초안 라벨 일치율**을 본다. 프롬프트는 `data_preparation/multilingual_vqa_pilot/INFERENCE_PROMPT.txt`, 선택지 문법은 `configs/choice_letter.gbnf`다. 모델·투영 파일은 `downloads/models/Qwen3.6-35B-A3B-GGUF/`에 있다. 이 수치를 공식 정확도로 부르지 않는다.
5. 질문·선지·정답을 바꾸면 **기존 예측은 무효**다. 새 로컬 추론을 마친 뒤 `build_multistep_review_csv.mjs`가 새 실행 결과를 참조하도록 하고 검토 CSV를 다시 만든다. 사람이 입력한 기존 검토 칸이 있는지 먼저 확인해 덮어쓰지 않는다. 이미지나 문항 ID가 바뀌면 `bundle_multistep_50_images.py`로 이미지 ZIP도 새로 만든다.

## 검수 때 발견해 반영한 사례

- `multistep_018`: 중국의 **대학 35곳에 소프트웨어 학원**을 신설한 것이지 대학 35곳 자체를 신설한 것이 아니다.
- `multistep_046`: `그 아래 몇 번째`와 `위에서 몇 번째`가 다른 답을 만들 수 있으므로 기준점을 명시한다.
- `multistep_013`~`017`: `이상`으로 적힌 두 하한값의 실제 차이·비율은 결정할 수 없어 수치-대상 대응 및 위치 관계로 바꿨다.
- `multistep_028`, `036`: 어색한 십년대 표현과 이미지에 없는 의미의 추론을 제거하고, 앞 문항과 동일한 계산도 피했다.
